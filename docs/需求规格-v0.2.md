# RiftStats 需求规格 v0.2

> 状态：待确认　｜　更新：2026-11-17
> 这份文档回答一个问题：**要做成什么样，才算做完了。**
> v0.1 已经有能跑的骨架（客户端直连 / 存档 / 统计 / 四个页面 / 单文件 exe），
> 下面是把它往"能发给朋友装的小工具"推的规格。

---

## 一、定位

**一句话**：一个装在 Windows 上、完全本地运行的对局数据工具，把"该不该赖队友"这件事
从感觉变成可检验的证据，并且明确告诉你：**证据够不够。**

边界（明确不做的）：

- 不做自动更新、不做账号体系、不上传任何数据。
- 不做"谁是内鬼"的判定。只输出**证据强度**：样本不足 / 无显著差异 / 显著偏低 / 显著偏高。
- 不做实时对局内的战术提示（那是另一类工具）。

## 二、三个真实场景（验收时按这个走）

| # | 场景 | 期望结果 |
|---|---|---|
| S1 | 想验证"跟某位固定队友一起容易被拖累"这个说法 | 打开软件 → 自动同步 → 队友页看到他的评级、样本量、效果量，以及"这个结论有多少把握" |
| S2 | 朋友把自己的对局拉进来看 | 装便携包 → 首次启动自动找到客户端 → 一键同步 → 不经过任何服务器 |
| S3 | 群里吵起来，需要一张能发的图 | 导出 PNG：某人的评级卡 + 样本量 + 方法说明一行 |

## 四、评级规则（本项目的核心，先钉死）

### 4.1 为什么不用"胜率 + 置信区间"下结论

上次那张表的问题不只是样本小。它把每个人单独和全局胜率比，但**同一局有 4 个队友**，
一局会被 4 行重复计入，各行的样本并不独立。独立性被破坏时，Wilson 区间会**低估**方差，
看起来"显著"的其实不显著。

所以主判据换成**置换检验**：在"队友身份与胜负无关"的假设下，把每局的队友组合整体打乱，
重算每个人的差值，重复 5000 次，得到零分布。实际差值落在零分布尾部多远处，就是 p 值。
这个方法天然处理重叠样本，也不需要假设正态。

### 4.2 判定流程

```
对每个队友 P：
  n = 与 P 同队的场次
  1) n < 20                        → 评级「样本不足」，不给方向
  2) n ≥ 20：
       观测值 d = 胜率(P) − 我的整体胜率
       置换检验（5000 次）→ p
       对所有被试者做 BH 校正 → p_adj（FDR = 0.1）
  3) 评级：
       p_adj ≥ 0.1              → 「无显著差异」
       p_adj < 0.1 且 d < 0     → 「显著偏低」
       p_adj < 0.1 且 d > 0     → 「显著偏高」
```

### 4.3 展示规则

- 评级旁边**必须**同时显示：n、效果量（百分点）、p_adj。
- 「样本不足」的人不排序、不参与"最坑队友"这类榜单，只列出名字和场次。
- 页面上常驻一行方法说明：`置换检验 5000 次，BH 校正 FDR=0.1，n<20 不出结论`。

### 4.4 已知的混淆因素（v0.3 处理）

- **我玩什么**：跟某人开黑时可能总补位，胜率变化被归到他头上。→ 按我的英雄/位置分层。
- **什么时候玩**：某个版本、某个时间段一起玩的局更集中。→ 按月分层。
- **模式不同**：大乱斗和峡谷不能混在一起算。→ 默认按模式分开，页面顶部标明。

## 五、数据模型变更

在现有 `Match` / `Participant` 基础上加：

| 字段 | 位置 | 用途 |
|---|---|---|
| `my_role`（我这一局的位置/英雄） | Match | 混淆因素分层 |
| `queue_id` / `game_mode` 细分 | Match | 模式分层 |
| `participant.gold/cs/vision`（已存） | Participant | 后续"是不是在送"类分析 |
| `friend_flag` + `friend_since` | 关系表（新增） | 好友/常玩/路人 |
| `puuid` 作为主键（而非名字） | Participant | 改名不丢数据 |

关系表用 `(my_puuid, other_puuid, relation, first_seen, last_seen)`，名字只做展示。

## 六、交付形态

```
RiftStats/
├── RiftStats.exe        # 单文件，约 50MB
├── data/                # 数据库（可改路径）
└── README.txt           # 三行说明：双击、同步、关掉
```

- 发朋友：打包成 zip，解压即用。不做安装包（省掉卸载、权限、杀软误报的麻烦）。
- 不写注册表；数据库默认在 exe 旁边，整个文件夹可以拷走。
- 单文件 exe 的代价是启动时解包到临时目录（首次约 2 秒）；若嫌慢，可改成 onedir。

## 八、验收清单（v0.2 完成定义）

- [ ] 在一台**没装 Python** 的电脑上解压 zip、双击能跑
- [ ] 客户端开着时，一键同步 200 场，去重正确，重复点不会重复入库
- [ ] 队友页能正确标出哪些是好友（来自客户端好友列表）
- [ ] 每个队友都有评级，且「样本不足」的人不会被排到最后一名当内鬼
- [ ] 自检脚本覆盖：评级阈值、置换检验的 p 值分布、BH 校正
- [ ] 断网状态全功能可用
- [ ] 数据只存在本地，删掉 data/ 即彻底清除

## 九、还需要拍板的三件事

1. **安装形态**：便携 zip（默认，推荐）还是做成安装包？
2. **评级阈值**：n ≥ 20 起步、FDR = 0.1。要更严格（n ≥ 30）还是更宽松（n ≥ 10）？
3. **要不要记"我这局玩什么"**：记了才能剔除"跟他玩就补位"的影响，但多一步数据依赖
   （LCU 里有，不用你填）。
